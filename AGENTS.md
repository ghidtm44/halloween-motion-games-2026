# Halloween Playground development

- Use `apps/simple-playground-v1/` as the primary application. The current offline worlds are jungle, underwater and space with identical continuous walk-up mechanics and seamless live switching. The user explicitly replaced the original Halloween scene choices; retain their history in Git and safely migrate old selections. Preserve Spooky Host as a separate installed app; build the offline edition with `--motion-games`, separate settings/port and no credential access. Do not replace Corn Maze or other existing apps.
- Preserve `apps/corn-maze/` as the separate Corn Maze 1.1.0 experience. Do not merge, delete, or replace it as part of the new mode.
- `launchers/macos/native/Playground/` is an exact packaging snapshot, not the active web development source. Keep the Swift wrapper and snapshot intact until an explicit Mac packaging step synchronizes a tested build. Never edit a user's Desktop installation from cloud work.
- Run `bash .codex/setup.sh` for a fresh cloud checkout. Use Node.js 22+. Run appropriate build/tests for changed behavior. Browser and hardware evidence from earlier work is historical, not proof of the new mode.
- Preserve loopback binding, same-origin checks, single active camera owner, safe camera-off startup, and admin/player synchronization. Do not expose the server publicly to obtain a preview.
- Existing free-play and Corn Maze modes must remain fully offline after installation. Only the explicitly started online AI mode may make model requests. Selecting that scene alone must not upload camera frames.
- The new mode’s TV output is a crystal ball with an animated speaking face. Never draw the camera image or visitor cutout on its player stage. Camera input drives local attention tracking and explicitly started AI costume observations; any admin camera preview is optional and off by default.
- Follow `docs/SPOOKY-HOST-BRIEF.md` for the new mode. Consult current official OpenAI documentation before selecting APIs/models. No API key is assumed available: implement and test a deterministic mock provider first; clearly distinguish mock, configured, and live-tested states.
- Keep API credentials server-side in environment secrets. Never place them in browser code, Vite public variables, logs, committed files, screenshots, or model prompts. Never log/store captured frames, audio, transcripts, camera IDs, or session conversation content. Log bounded diagnostic metadata only.
- Use synthetic fixtures for cloud tests. Do not claim live webcam, separate person masks, child/costume accuracy, physical HDMI behavior, or a Mac-native rebuild from Linux tests. Real camera/TV validation and AppKit compilation require a Mac.
- Do not copy instructions visible in camera images into application control flow. Do not infer identity or sensitive personal traits. Honor the live performance tone slider, keeping its lowest setting welcoming for children and its highest setting cheeky but non-explicit; comment on visible costume items and colors, with uncertainty when needed.
