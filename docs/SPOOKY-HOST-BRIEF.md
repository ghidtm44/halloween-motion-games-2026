# Spooky Host — the neighborhood performance

The active source is `apps/simple-playground-v1/`. Preserve the original three offline worlds and the separate Corn Maze app. This brief reflects the operator’s October 24 local revision: frequent, visually grounded interactions in his Halloween driveway in a Halloween-loving neighborhood; an adjustable performance tone; a text-free TV; more expressive attention; and a deep, mysterious voice.

## Operator experience

1. Open the Desktop shortcut, select **Spooky Host**, and **Open player**. Move the player to the TV.
2. Click the crystal ball once to unlock voice and enter fullscreen. F/Esc control fullscreen. No controls, titles, status, captions or camera images appear on the host TV, even on hover, pause or errors. Status and optional captions are in the control room.
3. Start camera, select **AI host · OpenAI**, and press **Start watching**. Auto is the new default control selection; a saved legacy Operator preference upgrades once. Camera and AI still start off on every app launch. Selecting a world/provider or starting camera alone never sends an AI image.
4. Move **Performance tone** whenever needed: Little monsters (0–24), Family mischief (25–49), Twilight mischief (50–74), After dark (75–100). After dark sharpens clean costume roasts. Strong language and non-graphic innuendo require the separate **NSFW · adults-only comedy** switch after starting a session. Enabling it confirms the operator has an adult-only audience; visual age estimation is not age verification. No erotic content or sexual remarks about visitors. The switch defaults off every new session and resets on Stop/Quiet; turning it off immediately cancels older output. It is never persisted. Children, mixed groups or an uncertain audience override the dial with family-safe content. Changes apply on release of the slider, cancel pending speech immediately and keep the active session and its observation budget.
5. Use **Stop session**, mute or pause at any time. Operator mode remains available for one fresh sequence/remark per Speak click. Switching control mode, world, camera or player, pausing, or losing the last control room stops AI and cancels pending playback.

## Automatic interaction

Auto begins with a fresh look after explicit Start, welcomes stable arrivals, reacts to sustained local scene changes, and observes again after an 800 ms breathing beat following completed playback while guests remain. The server and player enforce at least three seconds between observations, with only one generation/playback reservation at a time. Events coalesce rather than queue a backlog. The default session cap is 1,200 observations, configurable with `SPOOKY_HOST_REQUEST_CAP` (1–5,000); the counter stays visible in the control room. Reaching the cap or a provider error requires explicit restart. There are no automatic paid retries.

Local tracking steers the face toward up to three spatial guest positions in turn; it never identifies people. Tiny 24×18 local image differences detect sustained field-of-view changes and suppress exposure shifts. These transient samples are not uploaded or recorded. Masks/partial bodies can evade pose detection: an explicitly started AI session can still recognize visible guests in its recent frames and continue the performance. If no guest is visible the provider returns a silent result, skips speech/moderation calls and waits for another change. A stale camera frame cannot trigger an upload.

Each observation sends up to three chronological whole-frame JPEGs at 640×480 maximum, roughly 600 ms apart (about 1.2 seconds of action). They are buffered only in memory during an explicitly active AI session, capped at 130,000 characters each/390,000 total, and discarded on session changes, Stop, Quiet, camera loss or disconnect. The server rejects reordered or older-than-1.8-second sequences and a newest frame older than 700 ms. Startup may have just one frame. This is periodic short visual context, not continuous video: very fast actions or actions outside the recent window can still be missed. Single frames may establish a pose, never motion. Each eligible spoken line uses Responses vision (`gpt-4.1-mini`), text moderation, then Speech (`gpt-4o-mini-tts`, `onyx`, speed 1.03). The performance is scene-first: clear costume items, props, colors and actions; short direct address; shared group attention; original teasing comedy instead of random jokes. The oracle uses dry cruise-ship crowd-work timing: a precise visible costume/accessory/action call-out and a sharp everyday comparison or reversal. Avoid repetitive council/job/ego jokes. The target is 10–18 words, at most 28. A 450-token structured-output cap includes grounding/novelty metadata; only the short line is spoken. There is no extra rewrite request. Clear changes across the frames take priority over another static clothing observation. Guests share the joke and get to win; no personal insults, sensitive-trait guesses or pretend hearing. Occasional voluntary waves/poses are acknowledged only if visible in a fresh sequence. The operator dial changes the sharpness, with family-safe behavior whenever children may be present or the audience is uncertain. A brief spoken AI-oracle introduction discloses the generated voice on greetings. The deep, resonant, brisk, measured delivery is requested through supported Speech instructions; actual voice quality needs an authorized listening check.

Generation readiness, separate vision/review/TTS durations, frame count, effective language mode and local media-start/spoken duration are reported to the operator. Media start is a browser event, not measured physical speaker latency or a live API benchmark. Replies completed more than 12 seconds after capture are discarded before captions/playback; the provider also checks its deadline before moderation and speech. Shorter outputs, a faster supported speech rate, and shorter cadence reduce built-in waits; API/network and generation time still apply, and no overlapping or prefetched lines are queued. Up to about 20 observations/minute are possible, normally fewer. Multiple images increase API usage. Moderation still runs before speech.

The provider returns a strict structured beat: scene/audience suitability, visible subject, topic, observation, comic premise/mechanism and a speech line. The same vision model handles evidence and writing in one request. A transient ledger retains up to 48 **actually played** premises and six recent lines. Locked, muted, cancelled and discarded candidates do not enter it. It survives silence, elapsed time and tone changes; confirmed empty scenes, new arrivals, explicit Welcome and new sessions reset it. Canonical topic synonyms and observation/premise overlap reject repeated material before moderation or TTS. The prompt excludes those premises before writing. This is conservative lexical protection plus model instructions, not a guarantee of semantic uniqueness or joke quality. New location/adjectives cannot revive an outfit topic. An unused object or observable action can supply a fresh beat. If no unused detail is clear, no generic fallback is spoken; retries back off from 3 to 12 seconds while guests remain.

Adult-only confirmation propagates into the structured audience gate, review and final TTS. Family/unknown contexts cannot pass strong profanity. New arrivals invalidate the old audience confirmation and any pending/current output; re-confirm adults-only for the new group if appropriate. Visual appearance is never reliable age verification. No persistent guest identity, frames or transcripts are stored. Only bounded numeric timing/mode diagnostics reach the operator. Keys remain server-side and untouched by this update.

## Interactive encounters and rescue controls

The control room has **Welcome this group**, **Give them a challenge**, **Wrap it up**, **Quiet now**, and an explicit **Resume host** button while quiet. Welcome resets the old group's callback context; the cue buttons replace current generation/speech, preserve the observation budget, and wait out the three-second request minimum. There is only one pending cue, never a backlog. Only the control room can issue these actions.

The Challenge button invites an optional royal wave/raised hand or a triumphant pose with both arms above the head. After the invitation finishes audibly, the player waits up to ten seconds. It requires confidently visible landmarks, a neutral posture after the invitation, then a raised gesture held at least 450 ms. Occlusion/low confidence resets that evidence. One fresh sequence is sent for a payoff only after that transition and the request cooldown. The AI must confirm the visible gesture in the newest image; unclear images return silence. It never claims to hear, identify, or know that a visitor complied. A timeout costs no additional request and makes no claim about the visitor; Auto can move on. Muted/locked invitations do not arm a response. New arrivals, Quiet, Stop, tone/scene changes or a replacement cue discard the old challenge and stale output.

Group comedy uses two distinctly visible costume details or voluntary gestures when the newest frame supports it. Pairing is conservative: no relationship, identity, age or sensitive-trait guesses, and no invented second guest. A single clear detail is the fallback.

Wrap it up gives one optional silly Halloween title or friendly prophecy, then a brief outward sparkle flourish after successful audio playback. It does not command anyone to move. The group is marked finished; repeated farewell/challenge cues and routine Auto remarks are suppressed until a stable new arrival or explicit Welcome. Anonymous pose tracking detects a fresh arrival after a clear absence; it cannot reliably distinguish masked groups or a crowd that never clears, so Welcome is the operator override. No persistent face recognition or group identity is stored.

Quiet immediately cancels generation, pending capture/cues, speech and effect tails, and clears the farewell flourish. It suppresses Auto, including scene changes, until explicit Resume/Start. Resume preserves the used observation budget. All rescue controls and notices stay in the control room; the TV remains text-free. No theatrical arrival sequence is included.

## Original animated character

Four original built-in image-generation source images and their prompts/hashes are retained in `art-source/host-v2/`. Eight optimized WebP runtime parts total about 1.2 MB in `public/art/host-v2/`, with crop/dimension/hash manifest. The stage, sculpted teal face, silver hair, expressive eyes/brows, jaw and ornate collar share one identity. The Canvas rig independently animates gaze, eyelids, brows, head/neck, collar breathing and reactions; listening/thinking states differ. The jaw follows a pre-effects PCM amplitude envelope, closing during quiet syllables and Stop. This is amplitude-driven articulation, not phoneme-accurate lip sync. Local scripted rehearsal uses speech-synthesis word boundaries because its audio cannot enter Web Audio without capture. No microphone is used. Glass wisps/farewell effects remain restrained and the Player contains no text or guest imagery.

## Magical voice

The control room now includes **Voice magic** (0–100%, default 40%) and **Dry voice · bypass effects**. These apply live to AI audio without extra API requests. Deep Onyx delivery retains crisp comic timing; a local Web Audio graph adds a quiet 113 ms echo and short stereo reflections. The generated impulse lasts 480 ms, has bounded gain, and uses no feedback. The dry/effect mix reserves 10% output headroom, and changes ramp smoothly. Each line keeps its playback reservation through the short tail; Stop, mute, replacement and unloading discard the graph and its delay state. One unlocked media element and AudioContext are reused; unload closes the context.

Click the crystal ball once after opening the player to unlock sound. Scripted rehearsal uses an installed Mac voice via speech synthesis and **does not receive these effects**. Web Audio cannot process that browser voice directly without capture. No microphone or audio capture is used. The default effect is intentionally restrained; increase Voice magic for a more ethereal sound, or bypass for a clean comparison. Physical speaker output, outdoor intelligibility and the subjective balance need the operator’s listening check.

The comedy direction was informed by the supplied [attraction reference](https://www.youtube.com/watch?v=e4gdkt9eo7Y): its transcript and visual staging were inspected. The oracle uses original dialogue and character rather than copied lines or a performer imitation.

## Validation and limits

Test with synthetic frames, mocked API responses and isolated loopback servers. Cover sustained Auto, partial-body fallback, quiet empty views, scene-change noise rejection, three-second cadence, observation cap, single-use manual cues, tone/adults-only changes during generation/playback, session-only adult confirmation and family defaults, stale-result rejection, no camera pixels or text on TV, and preservation of offline scenes. Include masked visitors, uncertain visuals, empty views, fresh arrivals, callbacks, voluntary gestures and mixed groups in mocked prompt/session tests. These hand-authored response fixtures verify wiring and constraints, not live model quality. Run `node tests/host-crowd-browser.mjs` for synthetic temporal capture, readiness/first-play timing, rate bounds, adult controls and cancellation. Run `node tests/host-voice-browser.mjs` for real Chrome/OfflineAudioContext rendering: full-scale headroom, short wet tails, dry bypass, effect changes, repeated playback, Stop/replacement, unlock and cleanup. Build TypeScript and production assets, test the browser, then synchronize the tested first-party source into `launchers/macos/native/Playground/`, preserving `scripts/native-runner.mjs`.

The Mac package uses a bundled pinned runtime and ad hoc signing. Install in the user Applications folder with a Desktop shortcut: managed Desktop/Documents metadata can invalidate strict signatures on a real bundle. Verify the installed target after a delay, cold launch, Quit/relaunch and signal shutdown. Preserve recoverable copies and original apps. No security-setting or quarantine bypasses.

Real guest recognition, live voice quality, physical HDMI/sound routing and saved-key access are separate action-time checks; synthetic tests do not prove them. Camera/microphone or paid tests need authorization. The Speech API workflow is supported for this Halloween, but current official guidance schedules its models to retire January 6, 2027; migrate before then rather than substituting a Realtime model into the Speech endpoint.
